# Figma sync workflow

> **Code is the source of truth. Figma is an editable mirror.** PR approval
> includes a CI gate that fails if the Figma file is out of sync with
> `DESIGN.md`.

> **Default execution path is the Figma MCP, not human paste.** Agents that
> generate `.figma/push-patch.js` and stop are leaving the contract half-
> done. The whole round-trip — push the patch, re-export the snapshot,
> overwrite `.figma/figma-state.json` — is automatable via `use_figma`
> against the project file (`fileKey 72WgrM79k7HUcFHYVFgpfC`). Drive it.
> Manual paste is the fallback when the Figma MCP is unreachable (no
> Figma desktop session paired, MCP server down, etc.).

## What lives where

| Surface | Path | Role |
|---|---|---|
| Token authoring | `DESIGN.md` (frontmatter) | Canonical. Edits land here. |
| Generated CSS | `src/panel/styles/tokens.css`, `web/app/styles/tokens.css` | Auto-generated by `pnpm tokens`. Never hand-edit. |
| Figma snapshot | `.figma/figma-state.json` | Committed JSON dump of the Figma file's variables. CI compares against this. |
| Figma patch | `.figma/push-patch.js` | Auto-generated Plugin-API JS the designer pastes into Figma to apply DESIGN.md changes. Committed for review visibility. |
| Token-map schema | `scripts/lib/figma-token-map.mjs` | Single source for the Figma↔DESIGN.md mapping. Imported by all three sync scripts. |

## The four scripts

| Command | Direction | Purpose |
|---|---|---|
| `pnpm tokens` | DESIGN.md → tokens.css | Codegen for both panel + web outputs. |
| `pnpm tokens:check` | (drift check) | CI gate: tokens.css matches DESIGN.md. |
| `pnpm tokens:push` | DESIGN.md → Figma | Generates `.figma/push-patch.js`. Designer runs it in Figma. |
| `pnpm tokens:check-figma` | (drift check) | CI gate: `.figma/figma-state.json` matches DESIGN.md. |
| `pnpm tokens:pull` | Figma → DESIGN.md | Optional reverse path. Designers can edit values in Figma first, pull into DESIGN.md, then commit. |

## The two valid entry points

### A) Code-first (most common)

```
edit DESIGN.md
   ↓
pnpm tokens                 # regenerates tokens.css
   ↓
pnpm tokens:push            # writes .figma/push-patch.js
   ↓
use_figma  →  paste contents of .figma/push-patch.js, run it
              (fileKey 72WgrM79k7HUcFHYVFgpfC)
   ↓
use_figma  →  paste EXPORT_SNIPPET (bottom of scripts/sync-figma-tokens.mjs),
              save the returned JSON to .figma/figma-state.json
   ↓
pnpm tokens:check-figma     # local sanity (CI gates the same thing)
   ↓
commit DESIGN.md + tokens.css + .figma/push-patch.js + .figma/figma-state.json
```

### MCP execution recipe

For agents driving this from a Claude session:

1. Load the `figma-use` skill before any `use_figma` call.
2. **Push:** call `use_figma` with `fileKey: "72WgrM79k7HUcFHYVFgpfC"` and the
   body of `.figma/push-patch.js` as `code`. Expect a return like
   `{"created": [...], "updated": [...], "skipped": []}`. If `created` or
   `updated` is empty when DESIGN.md changed, the patch is stale —
   re-run `pnpm tokens:push` and retry.
3. **Re-export:** call `use_figma` again with the body of the
   `EXPORT_SNIPPET` (bottom of `scripts/sync-figma-tokens.mjs`) as `code`.
   It returns `{ meta: { variableCollections, variables } }`.
4. **Persist:** overwrite `.figma/figma-state.json` with that exact JSON.
   For minimal diffs, edit only the changed `valuesByMode` blocks instead
   of rewriting the whole file. Either is correct; minimal diffs are
   easier to review.
5. Verify with `pnpm tokens:check-figma`. Commit all four artifacts.

### B) Figma-first (exploratory)

```
[edit values in Figma directly]
   ↓
use_figma  →  paste EXPORT_SNIPPET, save returned JSON to .figma/figma-state.json
   ↓
pnpm tokens:pull --input .figma/figma-state.json
   ↓
pnpm tokens                 # regenerates tokens.css
   ↓
pnpm tokens:push            # regenerates .figma/push-patch.js (no-op patch — Figma already matches)
   ↓
pnpm tokens:check-figma     # passes
   ↓
commit
```

In both flows the end state is identical: DESIGN.md, both `tokens.css` outputs, the Figma file, and both `.figma/` artifacts all carry the same values.

## Where the snippets live

- **EXPORT_SNIPPET** — copy-paste block at the bottom of
  `scripts/sync-figma-tokens.mjs`. Reads variables from Figma and returns a
  JSON object in the exact shape `.figma/figma-state.json` expects.
- **push-patch.js** — auto-generated. The first run lands the full Figma
  state; subsequent runs only contain creates + updates.

## Add / update / remove semantics

| Change | What `pnpm tokens:push` emits |
|---|---|
| New token in DESIGN.md | `figma.variables.createVariable(...)` with `codeSyntax`, `description`, `scopes` set automatically. |
| Changed value | `setValueForMode(...)` for Dark and (if applicable) Light. |
| Renamed token | Treated as a remove + add. Patch will create the new variable; the old one is flagged for removal but **commented out** so the designer must manually uncomment to confirm deletion. |
| Removed token | Same as above — destructive, requires manual uncomment in `push-patch.js` before running. |

## Mapping table (Figma ↔ DESIGN.md ↔ CSS)

| Figma variable | DESIGN.md location | CSS var |
|---|---|---|
| `fg/X`, `bg/X`, `border/X` | `colors.<folder>-X` (Dark) + `colorsLight.<folder>-X` (Light) | `--<folder>-X` |
| `accent/X` | `colors.accent-X` (mode-agnostic) | `--accent-X` |
| `sp/N` | `spacing.N` | `--sp-N` |
| `radius/X` | `rounded.X` | `--radius-X` |
| `type/X` | `type.X` | `--type-X` |
| `tracking/X` | `tracking.X` | `--tracking-X` |
| `leading/X` | `leading.X` | `--leading-X` |

**Codebase-only** (not in Figma): `fonts.*`, `motion.*`, `ease.*`. The
sync scripts ignore these.

> **Tracking + leading caveat.** Figma's `setBoundVariable` for
> `letterSpacing` / `lineHeight` silently converts the property's unit from
> PERCENT to PIXELS, which breaks rendering. The variables exist in the
> Figma file as documentation tokens but are NOT bound to text styles or
> text nodes. Text styles instead carry literal `{unit: PERCENT, value: N}`
> values. The push script still updates these variable values so they stay
> in sync; designers shouldn't bind them by hand.

## CI gate

`.github/workflows/design-lint.yml` runs three checks on every PR that
touches `DESIGN.md`, `tokens.css`, `.figma/`, or `scripts/`:

1. `pnpm design:lint` — DESIGN.md frontmatter schema (existing).
2. `pnpm tokens:check` — DESIGN.md ↔ both `tokens.css` outputs match.
3. `pnpm tokens:check-figma` — DESIGN.md ↔ `.figma/figma-state.json` match.

A failure at step 3 means the designer didn't refresh the Figma file (or
forgot to re-export the snapshot). The error message points to the exact
recovery commands.

## Recovery — `tokens:check-figma` failed

```
✗ N drifts found:
  colors.accent-signal (Figma "accent/signal", mode Dark): DESIGN.md = #ff5500, Figma = #ff3d00.
  ...
To fix:
  1. pnpm tokens:push                   # writes .figma/push-patch.js
  2. use_figma — run .figma/push-patch.js against fileKey 72WgrM79k7HUcFHYVFgpfC.
  3. use_figma — run EXPORT_SNIPPET, write returned JSON to .figma/figma-state.json.
  4. Commit DESIGN.md, tokens.css, .figma/push-patch.js, .figma/figma-state.json.
```

## Why a snapshot file (vs. live REST)?

Figma's REST `variables/local` write API is Enterprise-only. Without
Enterprise access, CI can't write to Figma — only the designer's logged-in
session can. The snapshot pattern shifts the source of truth from "live
Figma file" to "the JSON we've committed", which:

- Makes CI fully offline (no FIGMA_TOKEN secret needed).
- Forces the designer to physically run the patch in Figma → re-export.
  This double-check catches errors before merge.
- Gives reviewers a diff: every PR with token changes carries a visible
  `.figma/figma-state.json` patch and a `.figma/push-patch.js` with the
  exact Plugin-API operations applied.

## Don't

- Don't hand-edit `.figma/figma-state.json` — it's the canonical record of what's actually in Figma. Editing it would silently let CI pass while Figma is wrong.
- Don't hand-edit `tokens.css` — it has an `AUTO-GENERATED` header for a reason.
- Don't add a new variable directly in Figma. Add the token to DESIGN.md, run `tokens:push`, paste the patch — that path keeps `codeSyntax`, `description`, and `scopes` consistent.
- Don't bypass the CI gate by force-merging when `tokens:check-figma` is red. The whole point is that Figma reflects code at every merged commit.
